# 错误与恢复文案

本文件是 Qwen Skill 的稳定错误映射。每个错误码只给用户一个中文说明和一个安全
下一步；文案不包含堆栈、原始错误体、审批指纹、凭据、链接或本地路径。

## 原则

- 只播报工具真实返回的错误码与状态，不猜测原因，不补写服务端没有返回的信息。
- 变更类工具（`submit_task`、`cancel_task`、`decide_approval`）失败后绝不
  静默重试；只有传输超时与临时不可用允许按工具契约重试一次，且载荷逐字节相同。
- 审批冲突必须先刷新 `list_pending_approvals` 或 `get_task`，再解释当前状态，
  然后询问用户是否继续。
- 每条文案都给出一个可执行的安全下一步，不要求用户重复提供已撤回的敏感信息。

## 稳定错误映射

| 错误码 | 场景 | 用户可见文案 | 安全下一步 |
|---|---|---|---|
| `AUTHENTICATION_FAILED` | 连接凭据无效或已过期 | 连接凭据无效或已过期。 | 请重新连接账号后再试。 |
| `RATE_LIMITED` | 服务端限流 | 服务端请求过多，暂时限流。 | 请稍等片刻再试，不要连续重复请求。 |
| `INVALID_REPOSITORY` | 仓库名称不在配置中 | 仓库名称不在配置的仓库列表中。 | 请从已配置的仓库名称或编号中重新选择。 |
| `CONNECTOR_OFFLINE` | Mac 连接器离线 | Mac 连接器当前离线，任务已保留。 | 请稍后重新提交，保留同一个请求编号。 |
| `IDEMPOTENCY_CONFLICT` | 请求编号重复 | 该请求编号已经存在。 | 请确认是否要新建任务，不要重复提交同一请求。 |
| `JOB_NOT_FOUND` | 任务不存在或已清理 | 没有找到该任务。 | 请重新列出任务并核对短号。 |
| `REVISION_CONFLICT` | 任务版本已变化 | 任务状态已变化，这次操作没有生效。 | 请刷新任务后再决定是否继续。 |
| `APPROVAL_EXPIRED` | 审批已过期 | 该审批已过期。 | 请刷新待审批列表，如仍需执行请重新发起。 |
| `APPROVAL_CHANNEL_UNAVAILABLE` | 审批通道不可用 | 审批通道当前不可用。 | 请稍后重试，或改用其他受支持的审批方式。 |
| `TRANSPORT_TIMEOUT` | 请求超时，结果未知 | 请求超时，结果尚未确认。 | 请重新读取任务结果确认实际状态，不要直接重复提交。 |
| `INTERNAL_ERROR` | 服务端内部错误 | 服务端内部错误。 | 请稍后重试一次，仍然失败请向维护者提供请求编号。 |

## 审批冲突的刷新规则

下列四个错误码表示审批上下文已经变化。处理方式固定为：先刷新待审批列表，说明
当前状态，再等待用户重新决定；绝不重放上一次决定，也不修改 `expected_job_revision`
后自动重试。

| 错误码 | 说明文案 | 刷新与下一步 |
|---|---|---|
| `REVISION_CONFLICT` | 任务状态已变化，这次决定没有生效。 | 刷新待审批列表后，请用户重新选择。 |
| `APPROVAL_EXPIRED` | 选中的审批已过期。 | 刷新待审批列表；如仍需执行，请用户重新发起。 |
| `APPROVAL_ALREADY_DECIDED` | 该审批已经被处理过。 | 刷新待审批列表并显示当前状态。 |
| `APPROVAL_SUPERSEDED` | 该审批已被新的操作取代。 | 刷新待审批列表并显示新的待审批项。 |

## 审批展示与确认

- 决策前必须紧邻调用 `list_pending_approvals`，序号只映射这一次列表。
- 列表最多五行，每行包含短号、动作、影响、风险与有效期；不展示审批指纹。
- 调用 `decide_approval` 前说一句包含动作与影响的确认；`expected_job_revision`
  只来自这次列表或紧邻的任务详情。
- 列表过期、序号缺失、序号超出或审批已过期时只澄清，不发出任何变更调用。

## 取消与竞态

- 取消前先解析唯一任务并读取当前版本，`cancel_task` 只调用一次。
- 队列中的任务取消后可能立即进入终态，直接播报返回的“已取消”。
- 运行中的任务取消后保持“正在取消”，直到后续查询返回终态。
- 取消与完成竞态时以服务端返回的终态为准，说明“取消未生效”，不再重复取消。

## 禁止内容

- 不展示堆栈、原始错误体、完整日志、审批指纹、凭据或本地路径。
- 不展示未由工具返回的状态、进度或失败原因。
- 不承诺由服务端主动发起通知或常驻监听。
