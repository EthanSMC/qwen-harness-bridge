## Experimental limitations (must ship with the release notes)

- Session-scoped only: one live session per owner; no cross-session continuation.
- No offline push: the Skill never claims background notification, push, or persistent
  listening.
- No replay or reconnect: an RTC disconnect ends the session; recovery is re-entering with
  a new session.
- Provider public-beta dependency: Aliyun RTC and DashScope ASR are public-beta services;
  region, quota and availability are provider-controlled.
- Best-effort speech: speech is bounded, may be interrupted by `STOP_OUTPUT`, and is not
  an accessibility guarantee.
- Stable query fallback: when RTC is unavailable, the stable task console (task list,
  detail, cancel, approvals, result) remains the supported path.
- Not part of the `v1.0.0` support SLO: the experimental RTC scope carries no uptime,
  latency or availability commitment beyond the provider's own beta terms.

## Disable and rollback

Set `QHB_RTC_ENABLED=false` (the default). The Control Plane mounts zero RTC routes and
zero provider factories, stable `/health/ready` and all seven MCP tools are unaffected,
and no Control Plane rollback is required. Drain active sessions for up to 90 seconds, then
force-close; see `docs/runbooks/rtc-provider-incident.md`.
